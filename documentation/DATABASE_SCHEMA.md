# ResearchOS – Database Schema

## 1. Overview

ResearchOS uses **PostgreSQL** as its primary relational database and the **pgvector** extension for storing and searching vector embeddings.

The database manages user accounts, research projects, conversations, uploaded documents, research findings, AI agent executions, evidence, and generated reports.

### Database Technologies

| Component | Technology | Purpose |
|---|---|---|
| Primary Database | PostgreSQL | Store structured application data |
| Vector Extension | pgvector | Store and search document embeddings |
| ORM | SQLAlchemy | Database operations through Python |
| Database Validation | Pydantic | Validate API data |
| Migrations | Alembic | Manage database schema changes |

---

## 2. Database Entities

ResearchOS will initially use the following entities:

| No. | Entity | Description |
|---|---|---|
| 1 | Users | Stores registered user information |
| 2 | Research Projects | Stores individual research projects |
| 3 | Conversations | Stores conversation threads associated with projects |
| 4 | Messages | Stores user and AI messages |
| 5 | Documents | Stores uploaded document metadata |
| 6 | Document Chunks | Stores extracted document text and embeddings |
| 7 | Sources | Stores web and academic references |
| 8 | Research Results | Stores findings generated by research agents |
| 9 | Agent Runs | Tracks AI agent execution details |
| 10 | Claims | Stores claims requiring verification |
| 11 | Evidence | Stores evidence supporting or contradicting claims |
| 12 | Reports | Stores generated research reports |

## 3. Table Structures

### 3.1 Users

Stores user account information.

| Column | Data Type | Constraint | Description |
|---|---|---|---|
| id | UUID | Primary Key | Unique user ID |
| name | VARCHAR(100) | NOT NULL | User's name |
| email | VARCHAR(255) | UNIQUE, NOT NULL | User email |
| password_hash | TEXT | NULL | Hashed password, if using password authentication |
| created_at | TIMESTAMP | NOT NULL | Account creation time |
| updated_at | TIMESTAMP | NOT NULL | Last update time |

### 3.2 Research Projects

Stores research projects created by users.

| Column | Data Type | Constraint | Description |
|---|---|---|---|
| id | UUID | Primary Key | Unique project ID |
| user_id | UUID | Foreign Key → Users.id | Project owner |
| title | VARCHAR(255) | NOT NULL | Research title |
| research_topic | TEXT | NOT NULL | Main research topic |
| description | TEXT | NULL | Project description |
| status | VARCHAR(30) | NOT NULL | Project status |
| created_at | TIMESTAMP | NOT NULL | Creation time |
| updated_at | TIMESTAMP | NOT NULL | Last update time |

### 3.3 Conversations

Stores conversation threads associated with research projects.

| Column | Data Type | Constraint | Description |
|---|---|---|---|
| id | UUID | Primary Key | Unique conversation ID |
| project_id | UUID | Foreign Key → Research Projects.id | Related project |
| user_id | UUID | Foreign Key → Users.id | Conversation owner |
| thread_id | VARCHAR(255) | UNIQUE, NOT NULL | LangGraph conversation thread identifier |
| title | VARCHAR(255) | NULL | Conversation title |
| created_at | TIMESTAMP | NOT NULL | Creation time |
| updated_at | TIMESTAMP | NOT NULL | Last update time |

### 3.4 Messages

Stores messages exchanged between users and AI agents.

| Column | Data Type | Constraint | Description |
|---|---|---|---|
| id | UUID | Primary Key | Unique message ID |
| conversation_id | UUID | Foreign Key → Conversations.id | Related conversation |
| role | VARCHAR(30) | NOT NULL | User, assistant, or agent |
| content | TEXT | NOT NULL | Message content |
| agent_name | VARCHAR(100) | NULL | Name of the responding agent |
| created_at | TIMESTAMP | NOT NULL | Message creation time |

### 3.5 Documents

Stores metadata about uploaded research documents.

| Column | Data Type | Constraint | Description |
|---|---|---|---|
| id | UUID | Primary Key | Unique document ID |
| project_id | UUID | Foreign Key → Research Projects.id | Related project |
| user_id | UUID | Foreign Key → Users.id | Document owner |
| filename | VARCHAR(255) | NOT NULL | Original filename |
| file_type | VARCHAR(50) | NOT NULL | PDF, DOCX, CSV, etc. |
| file_path | TEXT | NOT NULL | Storage location |
| file_size | BIGINT | NULL | File size in bytes |
| processing_status | VARCHAR(30) | NOT NULL | Upload and processing status |
| uploaded_at | TIMESTAMP | NOT NULL | Upload time |

### 3.6 Document Chunks

Stores extracted text chunks and their vector embeddings.

| Column | Data Type | Constraint | Description |
|---|---|---|---|
| id | UUID | Primary Key | Unique chunk ID |
| document_id | UUID | Foreign Key → Documents.id | Source document |
| chunk_index | INTEGER | NOT NULL | Chunk position |
| content | TEXT | NOT NULL | Extracted text |
| embedding | VECTOR | NULL | Vector embedding generated by an embedding model |
| metadata | JSONB | NULL | Page number, section, and other metadata |
| created_at | TIMESTAMP | NOT NULL | Creation time |

**Important:** The embedding column will use the pgvector vector type. Its dimensions must match the embedding model selected during implementation.

### 3.7 Sources

Stores references collected from web and academic research.

| Column | Data Type | Constraint | Description |
|---|---|---|---|
| id | UUID | Primary Key | Unique source ID |
| project_id | UUID | Foreign Key → Research Projects.id | Related project |
| title | TEXT | NOT NULL | Source title |
| url | TEXT | NULL | Source URL |
| authors | TEXT | NULL | Source authors |
| publication | TEXT | NULL | Journal, website, or publisher |
| published_at | DATE | NULL | Publication date |
| source_type | VARCHAR(50) | NULL | Web, academic paper, etc. |
| created_at | TIMESTAMP | NOT NULL | Collection time |

### 3.8 Research Results

Stores research findings generated by different agents.

| Column | Data Type | Constraint | Description |
|---|---|---|---|
| id | UUID | Primary Key | Unique result ID |
| project_id | UUID | Foreign Key → Research Projects.id | Related project |
| agent_run_id | UUID | Foreign Key → Agent Runs.id | Generating agent execution |
| source_id | UUID | Foreign Key → Sources.id, NULL | Related source |
| finding | TEXT | NOT NULL | Research finding |
| confidence_score | FLOAT | NULL | Agent confidence score |
| metadata | JSONB | NULL | Additional result information |
| created_at | TIMESTAMP | NOT NULL | Creation time |

### 3.9 Agent Runs

Tracks the execution of individual AI agents.

| Column | Data Type | Constraint | Description |
|---|---|---|---|
| id | UUID | Primary Key | Unique execution ID |
| project_id | UUID | Foreign Key → Research Projects.id | Related project |
| conversation_id | UUID | Foreign Key → Conversations.id, NULL | Related conversation |
| agent_name | VARCHAR(100) | NOT NULL | Agent name |
| status | VARCHAR(30) | NOT NULL | Pending, running, completed, failed |
| input_data | JSONB | NULL | Agent input |
| output_data | JSONB | NULL | Agent output |
| started_at | TIMESTAMP | NULL | Execution start time |
| completed_at | TIMESTAMP | NULL | Execution completion time |
| error_message | TEXT | NULL | Error details |

### 3.10 Claims

Stores factual claims extracted from research findings or generated reports for verification.

| Column | Data Type | Constraint | Description |
|---|---|---|---|
| id | UUID | Primary Key | Unique claim ID |
| project_id | UUID | Foreign Key → Research Projects.id | Related project |
| claim_text | TEXT | NOT NULL | Claim requiring verification |
| verification_status | VARCHAR(30) | NOT NULL | Supported, contradicted, or insufficient evidence |
| confidence_score | FLOAT | NULL | Verification confidence |
| created_at | TIMESTAMP | NOT NULL | Creation time |

### 3.11 Evidence

Stores evidence associated with claims.

| Column | Data Type | Constraint | Description |
|---|---|---|---|
| id | UUID | Primary Key | Unique evidence ID |
| claim_id | UUID | Foreign Key → Claims.id | Related claim |
| source_id | UUID | Foreign Key → Sources.id | Evidence source |
| evidence_text | TEXT | NOT NULL | Supporting or contradicting passage |
| evidence_type | VARCHAR(30) | NOT NULL | Supporting or contradicting |
| created_at | TIMESTAMP | NOT NULL | Creation time |

### 3.12 Reports

Stores metadata about generated research reports.

| Column | Data Type | Constraint | Description |
|---|---|---|---|
| id | UUID | Primary Key | Unique report ID |
| project_id | UUID | Foreign Key → Research Projects.id | Related project |
| user_id | UUID | Foreign Key → Users.id | Report owner |
| title | VARCHAR(255) | NOT NULL | Report title |
| format | VARCHAR(20) | NOT NULL | PDF, DOCX, or HTML |
| file_path | TEXT | NOT NULL | Generated report location |
| status | VARCHAR(30) | NOT NULL | Generation status |
| created_at | TIMESTAMP | NOT NULL | Report creation time |

## 4. Entity Relationships

The primary relationships are:

1. One User can create multiple Research Projects.
2. One User can own multiple Conversations.
3. One Research Project can have multiple Conversations.
4. One Conversation can contain multiple Messages.
5. One Research Project can contain multiple Documents.
6. One Document can be divided into multiple Document Chunks.
7. One Research Project can contain multiple Sources.
8. One Research Project can have multiple Agent Runs.
9. One Agent Run can generate multiple Research Results.
10. One Research Project can contain multiple Claims.
11. One Claim can have multiple Evidence records.
12. One Research Project can generate multiple Reports.

## 5. PostgreSQL and pgvector Integration

PostgreSQL will serve as the central database for ResearchOS.

The pgvector extension will enable vector similarity search for Retrieval-Augmented Generation (RAG).

### 5.1 pgvector Responsibilities

- Store document chunk embeddings.
- Perform semantic similarity searches.
- Retrieve relevant document chunks.
- Support retrieval for research questions.
- Work alongside keyword-based retrieval.

### 5.2 Vector Search Workflow

```text
Uploaded Document
       |
       v
Text Extraction
       |
       v
Text Chunking
       |
       v
Embedding Generation
       |
       v
PostgreSQL + pgvector
       |
       v
Similarity Search
       |
       v
Relevant Document Chunks
       |
       v
LLM Response with Citations
```

### 5.3 Hybrid Retrieval

ResearchOS will use hybrid retrieval:

- Vector Search: Finds semantically similar content using pgvector.
- Keyword Search: Finds relevant terms using PostgreSQL full-text search or BM25.
- Reranking: Reorders retrieved results based on relevance.

## 7. Data Security and Integrity

ResearchOS will follow these database security practices:

- Use UUIDs as primary keys.
- Enforce foreign key relationships.
- Use unique constraints for user email and conversation thread IDs.
- Store passwords only as secure hashes.
- Never expose database credentials in frontend code.
- Use environment variables for database configuration.
- Restrict users to their own projects and associated data.
- Validate API inputs before database operations.
- Use database transactions for operations requiring consistency.
- Configure appropriate backup and recovery procedures.

---

## 8. Database Migration Strategy

Alembic will manage database schema changes.

Migration workflow:

1. Define database models using SQLAlchemy.
2. Generate a migration using Alembic.
3. Review the generated migration.
4. Apply the migration to PostgreSQL.
5. Verify the updated database schema.

This approach allows the database structure to evolve as ResearchOS develops.
